# S3 Toolkit

Веб-сервис для управления S3-совместимыми хранилищами: бакеты и их настройки, объекты, ключи доступа и права пользователей в одном интерфейсе. Каждое действие, меняющее права, настройки или данные, записывается в журнал.

Один экземпляр сервиса обслуживает одну организацию: мультиарендности нет.

## Возможности

- **Хранилища.** Подключение по S3 API: AWS S3, Yandex Object Storage, Selectel, VK Cloud, MinIO, Cloudflare R2 и любое другое S3-совместимое хранилище. Есть проверка подключения перед сохранением. Ключи хранятся зашифрованными и больше не показываются.
- **Бакеты.** Список со статистикой (объём и число объектов считаются по запросу в фоне), создание (в том числе с Object Lock) и удаление со всем содержимым. Удаление — фоновой операцией с прогрессом и подтверждением вводом имени бакета.
- **Настройки бакета:**
  - версионирование и теги;
  - политика (форма или JSON, есть готовые шаблоны);
  - CORS;
  - правила жизненного цикла;
  - ACL;
  - хостинг статического сайта;
  - Object Lock со сроком хранения по умолчанию.
- **Объекты:**
  - навигация по «папкам», поиск по началу имени;
  - загрузка файлов и папок, в том числе перетаскиванием: крупные файлы идут частями с прогрессом и отменой;
  - скачивание;
  - удаление, копирование и перемещение (в том числе папок целиком, в фоне);
  - метаданные, теги, версии (скачать, восстановить, удалить), ACL, срок хранения и legal hold;
  - временные ссылки до 7 суток;
  - незавершённые multipart-загрузки.
- **Ключи доступа.** Создание, отключение и удаление S3-ключей через API провайдера. Секрет показывается один раз.
- **Пользователи и права.** Системные права и права на отдельные хранилища, шаблоны прав, суперадминистратор. Временный пароль нужно сменить при первом входе.
- **Журнал действий.** Записываются изменения пользователей и прав, хранилищ, настроек бакетов и ключей, удаления, перемещения и выдача временных ссылок. Можно искать и фильтровать по действию и дате. Входы в систему и загрузки файлов в журнал не попадают.
- **Обновление в реальном времени.** Ход фоновых операций приходит в интерфейс по WebSocket (Laravel Reverb).

Интерфейс на русском языке.

## Права

Права бывают двух видов: **системные** (на весь сервис) и **права на хранилище** (на одно хранилище целиком, включая все его бакеты).

Правила:

- выдавать права можно любому пользователю, кроме себя;
- тот, кто добавил хранилище, не получает на него прав автоматически;
- у суперадминистратора есть все права, ему права не выдаются;
- суперадминистратора может изменить только другой суперадминистратор, а последнего суперадминистратора нельзя заблокировать или удалить;
- шаблоны прав — именованные наборы; при выдаче набор копируется, и последующее изменение шаблона не меняет уже выданных прав.

### Системные права

| Право | Что даёт |
|---|---|
| Управление хранилищами | Добавлять, изменять и удалять подключения, задавать учётные данные управления ключами |
| Выдача системных прав | Назначать пользователям системные права |
| Выдача прав на хранилища | Назначать права на хранилища |
| Управление пользователями | Создавать, изменять, блокировать, удалять пользователей и сбрасывать им пароль. Нельзя менять пользователей, у которых есть системные права, которых нет у вас |
| Управление шаблонами прав | Создавать и изменять шаблоны |
| Просмотр журнала | Читать журнал действий |

### Права на хранилище

| Право | Что даёт |
|---|---|
| Просмотр бакетов и их настроек | Список бакетов, статистика, страница настроек |
| Создание бакетов / Удаление бакетов | Соответствующие действия |
| Управление политиками, CORS, жизненным циклом, версионированием, тегами, ACL, хостингом сайта, Object Lock | Изменение соответствующей настройки бакета (по праву на каждую) |
| Просмотр и скачивание объектов | Обозреватель объектов, свойства, версии, скачивание |
| Загрузка, копирование и перемещение объектов | Запись. Для копирования нужно ещё право на просмотр, для перемещения — на просмотр и удаление |
| Удаление объектов | Удаление объектов, версий и папок, отмена незавершённых загрузок |
| Создание временных ссылок | Публичные ссылки на объекты (вместе с правом просмотра) |
| Управление ключами доступа | Создание, отключение и удаление S3-ключей у провайдера |

> **Важно:** право «Управление ключами доступа» на практике равно полному доступу к хранилищу. Новый ключ получает права учётной записи, от имени которой создан. Выдавайте его только администраторам.

## Провайдеры

Набор функций по умолчанию задан для каждого провайдера. Если он не совпадает с вашим хранилищем, его можно поправить в настройках хранилища, например выключить ACL.

| Провайдер | Endpoint по умолчанию | Чего нет по умолчанию | Управление ключами | Проверено |
|---|---|---|---|---|
| AWS S3 | по региону | — | IAM: ключи пользователей | на заглушках API |
| Yandex Object Storage | `storage.yandexcloud.net` | — | статические ключи сервисного аккаунта | на заглушках API |
| Selectel | `s3.ru-1.storage.selcloud.ru` | Object Lock | EC2-ключи в OpenStack Keystone | на заглушках API |
| VK Cloud | `hb.ru-msk.vkcloud-storage.ru` | Object Lock | EC2-ключи в OpenStack Keystone | на заглушках API |
| MinIO | задаётся вручную | ACL, хостинг сайта, CORS | сервисные аккаунты (через `mc`) | **на настоящем MinIO** |
| Cloudflare R2 | `{accountId}.r2.cloudflarestorage.com` | всё, кроме CORS, жизненного цикла и списка загрузок | API-токены аккаунта | на заглушках API |
| Другое S3-совместимое | задаётся вручную | — | нет | — |

Всё, что касается S3 API, проверено на MinIO: объекты, бакеты, настройки, версии и Object Lock. Работа с API управления ключами Yandex, Selectel, VK Cloud, Cloudflare и AWS IAM написана по документации провайдеров и проверена только на заглушках. На реальном аккаунте её стоит проверить до того, как давать доступ пользователям.

### Учётные данные для управления ключами

Задаются на странице «Ключи доступа» хранилища. Сделать это может пользователь с правом «Управление хранилищами».

- **AWS** — ключ IAM с правами `iam:ListUsers`, `iam:ListAccessKeys`, `iam:CreateAccessKey`, `iam:UpdateAccessKey`, `iam:DeleteAccessKey`. Если поле пустое, используются ключи хранилища.
- **MinIO** — ключ с правами администратора на сервисные аккаунты, например root. Если поле пустое, используются ключи хранилища.
- **Yandex Cloud** — авторизованный ключ сервисного аккаунта (JSON из `yc iam key create`) с ролью `iam.serviceAccounts.accessKeyAdmin`.
- **Selectel / VK Cloud** — адрес Keystone, пользователь, пароль, домен и ID проекта. После смены адреса пароль нужно ввести заново.
- **Cloudflare R2** — Account ID и API-токен аккаунта с правом «Account API Tokens: Edit».

Ключи, которыми пользуется сам сервис (ключ хранилища и ключ управления), отключить или удалить из интерфейса нельзя.

## Как устроена работа с файлами

- **Загрузка идёт через сервер.** Файлы до 16 МБ передаются одним запросом. Более крупные браузер отправляет частями по 16 МБ, а сервер передаёт их в хранилище как S3 multipart upload. Прямого доступа браузера к хранилищу и настройки CORS для загрузки не нужно.
- **Скачивание — перенаправление на подписанную ссылку** (действует 5 минут), поэтому файл идёт из хранилища напрямую, минуя сервер. Хранилище должно быть доступно из браузера пользователя. Если сервер обращается к хранилищу по внутреннему адресу, например `http://minio:9000` внутри Docker, задайте у хранилища **публичный endpoint**: по нему строятся ссылки для браузера.
- **Операции над папками** (удаление, копирование, перемещение), удаление бакета и подсчёт статистики выполняются в фоне (очередь Horizon). Их прогресс виден в интерфейсе.

## Быстрый старт (разработка)

Нужны Docker и Docker Compose. Весь стек занимает около 650 МБ памяти, вместе с MinIO — около 1 ГБ.

```bash
cp .env.example .env
docker compose build
docker compose run --rm tools composer install
docker compose run --rm tools npm ci
docker compose run --rm tools php artisan key:generate
# Ключи Reverb: любые случайные строки
#   REVERB_APP_ID, REVERB_APP_KEY, REVERB_APP_SECRET — заполните в .env
docker compose up -d
docker compose exec app php artisan migrate
docker compose run --rm tools npm run build
docker compose exec app php artisan app:create-superadmin --name="Администратор" --email=admin@example.com
```

После этого сервис доступен на <http://localhost:8090>.

| Сервис | Порт на хосте | Назначение |
|---|---|---|
| app | 8090 | Octane + RoadRunner |
| reverb | 8091 | WebSocket |
| mariadb | 3307 | База данных |
| minio (профиль `s3`) | 9010 / 9011 | S3 и консоль для разработки |
| vite (профиль `frontend`) | 5174 | Dev-сервер фронтенда с HMR |

Чтобы запустить локальный MinIO, выполните `docker compose --profile s3 up -d minio` (логин и пароль `minioadmin`). В сервисе укажите endpoint `http://minio:9000` и публичный endpoint `http://localhost:9010`.

## Развёртывание

Пример для одного сервера — `compose.prod.yaml`. Образ собирается из цели `prod` в `docker/php/Dockerfile` и содержит код, зависимости, собранный фронтенд и клиент MinIO `mc`.

```bash
cp .env.example .env    # и заполните (см. ниже)
docker compose -f compose.prod.yaml build
docker compose -f compose.prod.yaml run --rm app php artisan key:generate --show   # значение — в APP_KEY
docker compose -f compose.prod.yaml run --rm app php artisan migrate --force
docker compose -f compose.prod.yaml up -d
docker compose -f compose.prod.yaml exec app php artisan app:create-superadmin --generate-password
```

Порты приложения и Reverb открыты только на `127.0.0.1`. Наружу их выставляет обратный прокси с TLS.

### Обратный прокси (nginx)

```nginx
server {
    listen 443 ssl http2;
    server_name s3.example.com;

    # Части загрузки — по 16 МБ
    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # WebSocket Reverb
    location /app {
        proxy_pass http://127.0.0.1:8091;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```

При такой схеме задайте `VITE_REVERB_HOST=s3.example.com`, `VITE_REVERB_PORT=443`, `VITE_REVERB_SCHEME=https`. Несмотря на префикс `VITE_`, эти значения читаются при запуске, и пересобирать фронтенд не нужно.

### Переменные окружения

Основные (полный список — в `.env.example`):

| Переменная | Описание |
|---|---|
| `APP_KEY` | Ключ шифрования. **Им зашифрованы ключи хранилищ:** если его потерять, их придётся ввести заново. Храните вместе с резервной копией БД |
| `APP_URL` | Внешний адрес сервиса (`https://s3.example.com`) |
| `APP_ENV=production`, `APP_DEBUG=false` | Боевой режим; в нём включены строгие требования к паролям (12+ символов, разные регистры, цифры, символы, проверка по утечкам) |
| `DB_*`, `DB_ROOT_PASSWORD` | MariaDB |
| `REDIS_*` | Redis: сессии, кэш, очередь |
| `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET` | Ключи Reverb (случайные строки) |
| `REVERB_HOST`, `REVERB_PORT`, `REVERB_SCHEME` | Адрес Reverb для сервера (внутри сети Docker: `reverb`, `8080`, `http`) |
| `VITE_REVERB_HOST`, `VITE_REVERB_PORT`, `VITE_REVERB_SCHEME` | Адрес Reverb для браузера |
| `TRUSTED_PROXIES` | Адреса обратных прокси через запятую или `*`. Нужен, чтобы в журнале был IP клиента, а схема определялась как https |
| `SESSION_SECURE_COOKIE=true` | Cookie сессии только по HTTPS |
| `STORAGE_ALLOW_PRIVATE_ENDPOINTS` | Разрешать endpoint во внутренних сетях (по умолчанию `true`, это нужно для MinIO в локальной сети). Если сервисом пользуются люди, которым нельзя давать доступ во внутреннюю сеть, поставьте `false`: иначе через endpoint хранилища можно обращаться к внутренним адресам (SSRF) |
| `STORAGE_CONNECT_TIMEOUT`, `STORAGE_TIMEOUT` | Таймауты запросов к хранилищам, секунды |
| `OPERATION_STEP_SECONDS` | Длительность одного шага фоновой операции (по умолчанию 20 с) |
| `SECURITY_CSP`, `SECURITY_HSTS`, `CSP_CONNECT_SRC` | Content-Security-Policy, HSTS и дополнительные адреса для `connect-src` |
| `MC_BINARY`, `MC_TIMEOUT` | Клиент MinIO для управления ключами MinIO |
| `OCTANE_WORKERS` | Число воркеров Octane в `compose.prod.yaml` |

### Резервное копирование

Достаточно базы данных MariaDB и значения `APP_KEY`. Сами данные лежат в хранилищах, сервис их не копирует.

### Обновление

```bash
git pull
docker compose -f compose.prod.yaml build
docker compose -f compose.prod.yaml run --rm app php artisan migrate --force
docker compose -f compose.prod.yaml up -d
```

## Безопасность

- Ключи хранилищ и учётные данные управления ключами хранятся в БД зашифрованными (`APP_KEY`). В интерфейс и журнал они не попадают.
- Есть Content-Security-Policy с nonce, HSTS по HTTPS и запрет встраивания во фреймы.
- Вход ограничен по частоте. Блокировка пользователя и смена пароля завершают его сессии.
- Временные ссылки нельзя отозвать до истечения срока (так устроен S3), поэтому их выдача записывается в журнал.
- Двухфакторной аутентификации пока нет.

## Известные ограничения

- В версионированном бакете **MinIO** удалённая папка может по-прежнему показываться в списке: там остались маркеры удаления, а MinIO отдаёт такой префикс как папку. Внутри она пуста. AWS так себя не ведёт.
- Срок временной ссылки — не больше 7 суток (ограничение подписи S3 Signature V4).
- Изменение метаданных объекта — это копирование объекта в себя (так устроен S3): в версионированном бакете появляется новая версия. Объекты больше 5 ГБ так изменить нельзя.
- Незавершённую multipart-загрузку может завершить или отменить любой пользователь с правом записи в хранилище, а не только тот, кто её начал.
- Управление ключами MinIO запускает `mc`. Каждое создание ключа ненадолго занимает около 100 МБ памяти в контейнере приложения: так шифрует данные Admin API MinIO.
